# GroupMatch

**GroupMatch** — веб-приложение для координации расписания группы и планирования встреч. Участники указывают свободное время, приложение строит тепловую карту пересечений, а владелец группы выбирает оптимальный слот.

## Возможности

- **Управление группами** — создание групп, приглашение участников по одноразовой ссылке, блокировка новых вступлений, передача владения другому участнику
- **Указание доступности** — каждый участник добавляет свои свободные окна; окна сохраняются между неделями. Соседние окна склеиваются, поэтому рабочая неделя занимает единицы слотов, а не десятки
- **Выделение жестом** — протяжка мышью по сетке отмечает время, протяжка по своим слотам стирает его; на тач-экране выделение начинается тапом и растягивается за ручки. Тап по своему слоту вместо этого открывает редактор: поменять время, скопировать на другие дни, удалить
- **Повторяющиеся слоты** — «каждый вторник и четверг с 10:00 до 12:00 до конца месяца» одной формой; серия разворачивается в обычные слоты, править и удалять её можно целиком
- **Массовая очистка** — стереть диапазон дней и часов одним действием, с предварительным прогоном, который показывает объём
- **Тепловая карта пересечений** — одна 30-минутная сетка с двумя слоями сразу: фон — сколько человек свободно, вставка внутри ячейки — своё время. Клик по заполненной ячейке предзаполняет форму создания встречи
- **Видно, кто именно свободен** — наведение на ячейку на десктопе или касание на телефоне показывает под таблицей имена всех, кто свободен в эту получасовку. По умолчанию выключено, включается владельцем для каждой группы
- **Встречи** — владелец планирует встречи из тепловой карты или вручную; экспорт в `.ics`
- **Удаление аккаунта** — из профиля. Группы, которыми вы владеете, сначала передаются другому участнику, опустевшие удаляются, а сам аккаунт обезличивается через 30 дней — в течение этого срока его можно восстановить
- **Тёмная тема** — переключатель светлой / тёмной / системной темы, сохраняется в `localStorage`
- **Профиль пользователя** — изменение имени и домашнего часового пояса
- **Обратная связь** — встроенная форма обратной связи (баги, пожелания, прочее)
- **Панель администратора** — список пользователей с поиском, блокировка, управление ролями и планами, список групп, разбор обратной связи
- **Гостевые аккаунты** — можно начать без регистрации и позже превратить гостя в полноценный аккаунт, сохранив все группы и слоты
- **Интерфейс на русском и английском** — переключается в профиле; письма приходят на том же языке
- **Уведомления** — колокольчик в приложении и письма: кто-то вступил в группу, назначена встреча, встреча через час. Каждый канал включается отдельно
- **Тарифы и подписки** — Free и Pro, оплата через ЮKassa (под флагом), бесплатный Pro для первых пользователей
- **Подписка на календарь** — `.ics`-фид группы, который календарный клиент обновляет сам
- **Промо-страница** `/promo` — отдельный лендинг со своими `robots.txt` и `sitemap.xml`
- **`/legal` и `/about`** — оферта, политика конфиденциальности и страница о проекте отдельными точками входа, а не маршрутами внутри SPA

## Локальная разработка

### Необходимое ПО

- Node.js 20+
- Java 25 (или JDK, совместимый со Spring Boot 4)
- Docker (для PostgreSQL через Testcontainers или локальный инстанс)

### Фронтенд

```bash
cd frontend
npm install
npm run dev                  # http://localhost:3000
```

Установите `VITE_MOCK_API=true` в `.env.local` для работы только в браузере с mock-данными (бэкенд не нужен). Установите `VITE_API_URL` для подключения к локальному бэкенду.

### Бэкенд

```bash
cd backend
# Запустите локальный Postgres или используйте Testcontainers для тестов
./gradlew bootRun            # http://localhost:8080
```

Переменные окружения бэкенда:

| Переменная | Описание |
|---|---|
| `SPRING_DATASOURCE_URL` | JDBC URL, например `jdbc:postgresql://localhost:5432/groupmatch` |
| `SPRING_DATASOURCE_USERNAME` | Пользователь БД |
| `SPRING_DATASOURCE_PASSWORD` | Пароль БД |
| `JWT_SECRET` | 256-битный секрет для подписи JWT |
| `SPRING_REDIS_URL` | URL Redis, например `redis://localhost:6379` |
| `CORS_ALLOWED_ORIGINS` | Разрешённые origins через запятую, например `http://localhost:3000` — должен совпадать с портом dev-сервера выше, иначе каждый запрос будет отбит CORS |

### Запуск тестов

```bash
cd backend
./gradlew test   # требуется Docker для Testcontainers
```

## Структура проекта

Фронтенд собирается как многостраничное приложение, а не как одна SPA:
`index.html` — само приложение, `promo.html`, `legal.html` и `about.html` —
отдельные точки входа со своими бандлами. Отсюда и отдельные каталоги под них
в `src/`.

```
groupmatch/
├── frontend/
│   ├── index.html        # приложение
│   ├── promo.html        # лендинг; /legal и /about устроены так же
│   ├── api/og/           # edge-функция Vercel: OG-превью для /join/:token
│   ├── vercel.json       # правила для точек входа выше + заголовки безопасности
│   └── src/
│       ├── api/          # Обёртки Axios + mock-слой
│       ├── components/   # Переиспользуемые UI-компоненты
│       ├── hooks/        # Выделение жестом, редактор слота
│       ├── pages/        # Страницы-маршруты; pages/group/ — экран группы
│       ├── store/        # Zustand-сторы (auth, theme)
│       ├── utils/        # Чистая логика: сетка, выделение, серии, разбор ошибок
│       ├── shared/       # Общее между приложением и отдельными страницами
│       ├── locales/      # ru.json / en.json
│       ├── promo/  legal/  about/   # точки входа отдельных страниц
│       └── types/        # Общие TypeScript-типы
└── backend/
    └── src/main/java/com/groupmatch/
        ├── config/       # Security, CORS, Jackson, проверки на старте
        ├── controller/   # REST-контроллеры
        ├── domain/       # JPA-сущности + enum'ы
        ├── dto/          # Записи запросов / ответов
        ├── exception/    # Свои исключения + @RestControllerAdvice
        ├── filter/       # Ограничение частоты запросов
        ├── job/          # Плановая уборка и обезличивание
        ├── repository/   # Spring Data JPA репозитории
        ├── scheduler/    # Напоминания
        ├── security/     # JWT-фильтр, принципал, определение адреса клиента
        ├── service/      # Бизнес-логика
        └── util/         # Мелкие общие помощники
```

## Участие в разработке

- Ветки `feature/*` создаются от `develop`; PR открывается обратно в `develop`
- Ветки `hotfix/*` создаются от `main`; PR в `main` и в `develop`
- `develop` → `main` мержится при релизе
- CI (lint, type-check, тесты, сборка) должен пройти перед любым слиянием
